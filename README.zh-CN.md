# Astera Intervention Hub

[English README](README.md)

Astera 是一个由 AI 辅助的技术干预平台，面向中小企业、自由职业者、超级个体和精品技术团队。

平台用于解决一个具体问题：企业可能知道某个技术问题正在影响增长、可靠性或安全性，但不一定知道如何诊断问题、明确范围，或安全地委托修复。Astera 将这种不确定性转化为受保护、可衡量的技术干预流程。

## 产品理念

Astera 不是普通的自由职业市场，而是将以下能力结合在一起的技术执行平台：

- 使用 AI 将模糊的业务痛点翻译为技术里程碑
- 在分享敏感业务信息之前，进行隐私安全的范围界定
- 根据公开证明材料和项目证据生成供应商能力档案
- 为个人提供基于 Vipps 的真实姓名验证流程
- 支持 ENK 和 AS 企业实体验证概念
- 通过基于里程碑的智能托管支付和证据驱动的付款释放保护交付
- 从速度、可靠性和质量多个维度建立信誉
- 当公开信号显示存在可避免的技术风险时，允许供应商主动联系客户
- 支持漏洞赏金、预防性诊断和弹性供应商团队

核心承诺很简单：在工作开始前降低不确定性，让交付证据清晰可见，并在昂贵的技术事故发生之前帮助企业进行预防。

## 网站流程

### 首页

首页介绍平台定位，并将访客引导至适合其角色的体验。

### 需求方：`/demand`

面向企业和其他需求方：

- 用日常语言描述技术问题
- 将问题转化为结构化技术简报
- 通过匿名化范围界定保护敏感业务信息
- 查看供应商匹配、项目里程碑、预算和交付风险
- 使用托管支付和里程碑证据保护项目执行

### 供应方：`/supplier`

面向技术供应商和解决者：

- 从 GitHub、LinkedIn、YouTube、简历和项目页面生成能力档案
- 整理技术技能和经过验证的公开信号
- 发现结构清晰且匹配度高的项目机会
- 识别潜在客户公开可见的技术风险
- 发送范围明确、尊重客户且需要审核的预防性联系信息
- 参与漏洞赏金和弹性交付小队

### 信任：`/trust`

信任控制层展示以下能力：

- 个人通过 Vipps 进行真实姓名验证
- ENK 经营者与组织编号验证
- AS 授权人员与公司身份验证
- 保护隐私的身份验证状态
- 显示已锁定、审核中和已释放状态的智能托管支付
- 基于证据的交付和多维度信誉

### 工作区：`/workspace`

用于演示匹配与交付之间产品层的交互页面：

- 需求方与供应方角色视图
- 可解释的供应商匹配分数
- 里程碑状态和证据审查
- 速度、可靠性和质量等信誉信号
- 从草稿到审核队列的主动联系流程
- 用于展示匿名化模式、同行基准和可复用工作手册的集体智能视图

### 集体智能

当平台积累了足够多经过验证的客户、供应商、干预项目和交付证据后，Astera 可以建立保护隐私的学习层：

- 将反复出现的技术挑战聚合为可识别的模式。
- 在不暴露其他客户身份或原始指标的前提下，向企业提供相关同行基准。
- 将成功的证据链转化为可复用的诊断和交付工作手册。
- 持续改进 AI 信息采集、匹配、预防建议和供应商推荐。

该层应采用用户同意、聚合阈值、匿名化、来源追踪、人工审核和删除控制。私密需求简报、客户名称、原始财务指标和专有证据不应自动进入共享洞察层。

当前的 Vipps 和企业验证交互是前端概念流程。正式产品需要连接 Vipps Login/API，以及适用的挪威企业组织注册或验证服务。

## 演示范围

该仓库是一个适合产品展示的前端概念。交互示例使用本地 React 状态，因此无需外部服务即可演示产品逻辑：

- 输入公开 URL 后模拟生成能力档案。
- 展示带有匹配原因的可解释供应商评分。
- 在工作区中选择并查看里程碑证据。
- 让主动联系从草稿依次进入审核和审核队列状态。
- 在模式、基准和工作手册之间切换集体智能视图。

本演示不会声称执行真实身份验证、支付、托管、AI 推理、数据采集或消息发送。

## 技术栈

- Next.js 14 与 App Router
- React 18 和 TypeScript
- Tailwind CSS
- Framer Motion
- Lucide React 图标
- 使用 Python 和 `python-pptx` 生成配套战略演示文稿

## 本地运行

安装依赖：

```bash
npm install
```

启动开发服务器：

```bash
npm run dev
```

打开 [http://localhost:3000](http://localhost:3000)。

创建生产版本：

```bash
npm run build
```

## 产品原则

1. 信任应当可观察，而不只是口头声明。
2. 隐私应当内置于范围界定和信息披露流程中。
3. 资金应当跟随可验证的结果释放。
4. 公开技术信号应当用于预防，而不是公开羞辱。
5. AI 应当减少歧义，同时让重要决策保持可审查。
6. 市场增长应当保持质量，而不是用规模换取质量下降。
